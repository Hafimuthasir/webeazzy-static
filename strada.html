How it works

A database without a backend — safely

Your app talks to Strada straight from the browser or phone. Two keys and rules inside Postgres keep each user to their own data.

Create your tables

Add tables in the dashboard, or let your AI assistant do it over MCP. Every table gets a server-generated id and starts private.

Choose who can see what

Pick a rule per table: public read, any signed-in user, or only each user's own rows. Add your site to the allowed origins.

Call it from your app

Use the publishable key (strada_pk_) in browser or app code. The secret key (strada_sk_) stays on servers — the SDK refuses to run with it in a browser.

Row security runs inside Postgres, not just in the API

On an "own rows only" table, Strada fills in the owner column on insert and refuses attempts to change it. The API filters every query, and Postgres enforces it too: signed-in requests run as a restricted database role with a row-level security policy, so even an unfiltered query cannot read another user's rows.

Low-cost Postgres

Stop paying database prices for your history

Most apps have a few tables that only grow: orders, bills, events, logs. Strada keeps the rows that still change in Postgres and moves settled ones to low-cost object storage — automatically, by a rule you set. That is how Strada stays a cheap Postgres database as your app grows.

  • You set the rule. For example, "paid orders older than 3 days". A background mover handles the rest, in batches, without duplicating rows.
  • One query reads both. select({ tier: "all" }) merges live and archived rows into one sorted, paged result.
  • Reports without downloads. Count, sum, average, minimum or maximum per day, week, month or year across both tiers.
  • Same rules, same ids. Archived rows keep their ids and the table's access rules, and can be moved back if you need to edit them.

Developer experience

A few lines from sign-in to data

Download the SDK as one file, create a client with your project ID and publishable key, and start reading and writing rows. Signed-in users automatically get only what the table's rules allow.

  • TypeScript and plain JavaScript versions
  • Filters, sorting and paging on every select
  • Prefer plain HTTP? Send X-Strada-Key to the REST API from any language.
Read the SDK docs
todos.ts
import { createClient } from "./lib/strada";

const strada = createClient(
  "https://strada.webeazzy.com",
  "YOUR_PROJECT_ID",
  import.meta.env.VITE_STRADA_PUBLISHABLE_KEY,
);

// Sign the user in
await strada.auth.signIn({ email, password });

// Only this user's rows come back
const { data: todos, error } = await strada
  .from("todos")
  .select({
    filters: [
      { column: "done", operator: "eq", value: false },
    ],
    sort: [{ column: "title" }],
    limit: 20,
  });

await strada.from("todos").insert([
  { title: "Buy milk", done: false },
]);

Questions

Strada FAQ

What is backend as a service?

Backend as a service (BaaS) gives your app the parts every backend needs, such as a database, user sign-in and an API, as a hosted service. You call it from your app instead of writing, hosting and patching a server of your own. Strada is a backend as a service built on Postgres.

Do I need a backend server to use Strada?

No. Your web or mobile app calls Strada directly with a publishable key. Access rules and per-user row security are enforced by Strada and by Postgres itself, so each user only sees the rows they are allowed to see. If you also run a server, it can use a secret key for full access.

Is it safe to put the publishable key in my frontend?

Yes. The publishable key (strada_pk_) only works from the website origins you allow, and only for what each table's access rules permit. Tables are private until you open them. The secret key (strada_sk_) has full access, belongs on servers only, and the Strada SDK refuses to run with it in a browser.

Is Strada a real Postgres database?

Yes. Your tables are PostgreSQL tables with typed columns, relations, unique rules and indexes, and per-user rules run as PostgreSQL row-level security. You work with them through the dashboard, the REST API, the SDK, a read-only SQL editor and the MCP server.

How does Strada stay cheap as my data grows?

Tables that keep growing, such as orders, bills, events and logs, can be tiered. You set a rule, for example paid orders older than three days, and settled rows move to low-cost object storage in the background with the same ids and values. The same query reads both tiers, and reports total them without downloading every row.

Is Strada a Firebase or Supabase alternative?

Yes. Like Firebase and Supabase, Strada gives your app a database, user sign-in and an API without a server of your own. Strada is built on Postgres and moves settled rows to low-cost storage automatically. It does not offer file storage, realtime subscriptions or serverless functions. See our Strada vs Firebase and Strada vs Supabase comparisons for details.

Can I use Strada from a mobile app?

Yes. The JavaScript/TypeScript SDK is a single dependency-free file, and apps on any other platform can call the same REST API over HTTPS with the publishable key and the signed-in user's access token.

Which AI coding assistants work with Strada?

Strada runs a hosted MCP server. The dashboard has ready-made setup for Claude Code, Cursor, VS Code with GitHub Copilot, Codex, Claude Desktop, Windsurf and Gemini CLI. Agent keys can be read-only.
